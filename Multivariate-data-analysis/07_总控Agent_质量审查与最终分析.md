# 总控 Agent｜质量审查与最终分析

## 任务
统一审核所有 Agent 输出，确保多源数据可以合并、复核并进入正式统计分析。

## 输入
Agent 1–6全部输出。

## 必查项目

### 1. 主键一致
所有文件必须包含：
- `participant_id`
- `condition`
- `run_id`
- `event_id`

### 2. 时间一致
- 时间单位全部为秒。
- 所有事件相对时间以 `event_onset = 0 s`。
- 原始时间戳必须保留。

### 3. 缺失值
区分：
- 真实未发生
- 数据缺失
- 无法编码
- 指标不适用

禁止统一填 0。

### 4. 指标定义一致
同名指标必须使用同一公式。

### 5. 数据质量
重点检查：
- AOI重叠/空档
- `UNCODABLE`异常偏高
- 行为日志开关未配对
- 次任务窗口无题目
- ID错位
- 事件窗口越界

### 6. 机制解释
所有机制结论至少回答：
1. 访谈说了什么？
2. 眼动支持什么？
3. 行为日志支持什么？
4. 次任务是否提供额外证据？
5. 是否存在冲突或替代解释？

## 最终统计单位
优先保留事件级数据：

`participant × condition × event`

同一被试存在多个事件时，统计分析必须考虑重复测量结构。

## 最终结果结构
### A. 客观行为层
- HMI查看
- 场景监测
- AOI切换
- 解释卡操作
- 次任务表现

### B. 过程机制层
- 持续监测
- 注意切换
- HMI依赖
- 认知负荷/注意冲突

### C. 多源验证层
- 一致支持
- 部分支持
- 冲突
- 边界条件

## 最终交付
- 清洗后的事件级主表
- 指标字典
- 多源证据矩阵
- 典型时间轴图
- 机制分析结果
- 数据质量报告
